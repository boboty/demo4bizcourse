# 财务演示套件运行手册

## 课前准备

```bash
./scripts/setup.sh
./scripts/test.sh
```

启动：

```bash
./scripts/run.sh
```

打开 `http://127.0.0.1:8001/demo`。每个页面顶部都有返回总览、全屏、讲师说明和重置；控制器支持上一步、下一步、自动播放、暂停、继续、重新开始、任意步骤跳转和最终结果。

## 建议课堂顺序

### 1. 企业知识回答对比

访问 `/demo/knowledge-answer`，按 01 → 05 推进。

- 先展示 58,600 元收款和付款方。
- 展示通用回答：合理但不知道企业实际口径。
- 展示企业资料：科目表、客户档案、内部规则、历史凭证、未核销应收。
- 强调同金额不是充分证据。
- 收尾：回答更准确了，但凭证未生成、核销未执行、任务仍待处理。

### 2. 批量流水固定工作流

访问 `/demo/batch-workflow`，按 01 → 06 推进。

- 固定批次为 40 笔。
- 37 笔生成凭证草稿，3 笔待调查，0 笔自动过账。
- 在第 04 步突出核心异常 58,600 元收款。
- 第 06 步点击“查看异常流水如何处理”，进入演示三并携带批次号。

### 3. 异常流水智能体

访问 `/demo/exception-agent`，或从演示二跳转。

- 左侧观察任务推进时间线，中间观察证据工作台，右侧始终展示权限边界。
- 重点停顿在同金额候选、历史回款和附件缺失。
- 第 07 步展示“自动处理已停止”。
- 第 08 步展示待人工确认任务和任务承接四问。
- 可选尾声模拟上传付款通知，生成草稿并提交会计复核，仍不自动过账。

### 4. 独立验收发现业务错误

访问 `/demo/independent-validation`。

- 先读正确规则，再读错误理解。
- 展示实现、单元测试、集成测试和回归测试全部 PASS。
- 让学员选择错误层次，再揭示“对原始业务规则理解错误”。
- 最后展示“验收未通过”。

### 5. 系统结转损益与结账

访问 `/demo/month-close`。

- 先做结账前检查。
- 点击“确认开始结账”，明确人工确认边界。
- 展示确定性规则生成结转损益和完成结账。
- 以“大模型、知识库、工作流、智能体、传统系统各自承担合适环节”收束。

## 现场兜底

1. 页面运行异常：使用控制器的“直接最终结果”展示最终判断。
2. 时间不足：使用步骤下拉菜单跳到核心反转步骤。
3. 浏览器不稳定：使用 `demo_assets/screenshots/SCREENSHOT_PLAN.md` 准备的关键截图。
4. 需要脱离现场操作：使用 `demo_assets/recording/RECORDING_PLAN.md` 录制的本地视频或讲师手卡。
