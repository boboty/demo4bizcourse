提示词 A · 需求变更影响分析（V1.0 → V1.1）

自带 V1.0 基线、财务规范、V1.1 三项变更、历史场景与全部历史用例；粘贴到全新的 AI 对话。

你是一名测试资产维护顾问。悦选商城售后需求从 V1.0 升级到 V1.1。请只依据下面的材料，分析这次变更对既有测试资产的影响，并给出每条历史用例的处置建议：保留 / 修改 / 作废，以及需要新增的用例。

【判断原则】
- 沿“变更 → 规则 → 场景 → 用例”的依赖链判断，不要凭印象；
- 区分“行为或断言发生变化（需要修改/作废/新增）”和“只是需求来源或依据被更新、行为与金额不变（仍可保留）”；
- 能保留就不要重建，避免为凑数量而重做已验证的资产；也不要漏掉真正受影响的用例。

【V1.0 基线需求】
P10：消费者可在订单签收后7日内提交退货申请；申请需选择退货商品和数量，并填写原因。
P20：客服审核申请。审核通过后，消费者按页面提供的地址寄回商品并填写物流单号。
P30：仓库签收退货后检查商品；质检通过的商品进入退款处理，未通过时由客服联系消费者处理。
P40：退款退回原支付渠道。部分退货按商品实付金额退款；优惠分摊及退款金额以财务规则为准。
P50：页面展示售后申请、审核、待寄回、运输中、仓库签收、质检、退款中、已退款及已关闭等处理状态。
P60：订单支持银行卡或余额支付，可同时使用满减优惠；用户可在订单详情发起售后。

【V1.0 业务规则】（规则ID｜内容）

【已独立验证的财务规范（历史金额用例的依据）】
F10：部分退货后，以剩余商品原价合计重新判断满减门槛；未达门槛时，剩余订单优惠为0。
F20：按同一订单已经退款的SKU集合计算累计退款：本次退款=原订单实付-(退货后剩余商品原价-按剩余商品重算的优惠)-此前已退款。
F30：同一订单多次部分退款使用已退SKU集合累计计算；金额下限为0，上限为原订单实付减此前已退款，不得负退款或超付。重复退同一SKU不得产生第二次退款。
F40：按F20计算出的本次退款小于0时，不执行负数退款，暂停自动退款并转财务人工复核；厘清差额前不记为独立验证通过。

【V1.1 三项变更】（变更ID｜对应规则｜新增或替换的需求原文）
C10｜R-FAST-REFUND｜P31：当订单输入中的极速退款资格标识 eligible=true 时，消费者填写退货物流单号后即可退款，不等待仓库质检；质检仍继续进行，失败时转客服处理并追偿。符合资格与否由上游标识给出，本需求 不推定资格算法。
C20｜R-RETURN-WINDOW｜P11：退货期限以签收时刻起算：普通及银卡会员7日，金卡会员15日；以提交订单时记录的会员等级判定。时间统一使用订单时区的时间戳，截止时刻含在期限内（<=7×24小时或<=15×24小时），超出1秒拒绝。
C30｜R-PROMO-RECALC｜P41：部分退货退款时，按退货后剩余商品重新计算满减优惠。按同一订单已退SKU集合累计：本次退款=原订单实付-(退货后剩余商品原价-按剩余商品重算的优惠)-此前已退款；计算为负时暂停并交财务复核，不产生负数退款。累计退款不得超过订单实付。
