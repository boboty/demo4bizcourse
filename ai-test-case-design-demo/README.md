# AI赋能业务测试用例设计与优化 · 悦选商城 Demo

独立、可运行、可测试的离线课堂演示，连续覆盖 Demo 2～6。课程开场继续使用既有 `mnist-3d`，本项目未复制或修改它。只包含运行所需的最小需求、规则、场景、测试与冻结 AI 输出；不包含整套课件或测试管理平台。

Python 3.9+、FastAPI、原生 HTML/CSS/JavaScript，无数据库、CDN、在线字体或 LLM API。**AI 内容明确标为预置演示结果；金额、测试报告、预算裁剪与增量统计由代码实际执行。**首次安装依赖需联网或使用事先准备的本地包；安装完成后核心演示不需要网络。

## 安装、启动、课前自检

在仓库根目录执行：

```bash
cd ai-test-case-design-demo
make setup
make validate    # 最终必须出现 DEMO READY
make dev
```

访问 <http://127.0.0.1:8016>。其他 Demo 使用不同目录与依赖环境；本项目默认端口为8016。端口被占用时使用 `PORT=8026 make dev`，并访问对应地址。

已安装依赖后也可直接运行：

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8016
.venv/bin/python -m pytest -q
.venv/bin/python scripts/validate_demo.py
.venv/bin/python scripts/reset_demo.py
```

`validate_demo` 是只读自检：检查材料、版本隔离、规则/场景/用例引用、20条假设测试、32条可信历史及目标候选、三项变更、25条实际回归、49元与累计退款；还会启动并关闭临时端口上的真实服务，检查页面、静态资源与全部课堂入口。它不依赖已经启动的8016服务，不改变课堂阶段。失败时输出 `DEMO NOT READY` 并返回非零退出码；这不是投影设备视觉验收。

## 课堂顺序与操作

先运行 `make reset` 或点击“全局重置”，起点为 Demo 2／阶段1，预算15，未补漏、未执行、未揭示。建议以1366×900或更大窗口投影。顶部按钮切换 Demo；“上一步／下一步”推进阶段，详细资产折叠展示。

| Demo | 起点与点击顺序 | 观察与讲述 |
| --- | --- | --- |
| 2：太早生成 | Reset → Demo 2阶段1 → 展开12条冻结用例及PRD → 下一步查看八维分析 → 下一步查看场景地图 | 同一份V1.0；绿色事实、黄色推断、红色缺失/冲突。核对金额、7日期限、客服超时、运费与渠道失败的依据。“问题不是AI不会生成，而是太早让它生成。” |
| 3：展开→裁剪→补漏 | 点击Demo 3 → 候选41条/理论432组合 → 切预算10、15、20 → 下一步“人工补回SC36” → 下一步覆盖矩阵 | 数量等价类抽样后40个候选；保护正常申请/正常质检，再按影响×概率×难发现度排序。补回金卡+混合支付+优惠失效+渠道超时，会替换一个低优先场景，预算不增加。未覆盖与依据未确认分别看。 |
| 4：全绿但业务错 | 点击Demo 4阶段1 → 查看订单和假设用例 → “执行20条测试” → 全绿报告 → “揭示财务规范” | 20条真实调用比例分摊实现，全部符合假设预期；随后加入独立财务规范，人工复算退款49.00。通过只证明符合测试预期，预期本身也需验证。 |
| 5：增加信息源 | 点击Demo 5 → 第一轮审查输入与冻结报告 → 下一步增加财务来源 | 第一轮能提醒来源不足，但不能证明应退多少；第二轮明确发现85.13预期错误。“换一个AI，不等于增加新的事实。” |
| 6：增量更新 | 点击Demo 6 → 已验证V1.0 → V1.1三变化 → Rule Diff → 规则/场景/历史用例定位 → 处置与Before/After → 回归结果 | 极速退款、下单金卡15日、优惠规则正式化。保留/修改/作废/新增由引用与断言推导；来源更新不等于金额算法改变。25条回归实际执行，并展示排除理由。“效率来自不用每次从头开始。” |

支持键盘2～6选择 Demo、方向键切阶段、R复位（按钮或展开控件获取焦点时优先按其原生键盘行为操作）。Demo末步直接点击顶部下一个Demo；不要在Demo之间Reset，否则会清空课堂操作状态。

## 固定业务事实与金额复核

经典订单：A=199、B=99、C=59，原价357；满300减50，实付307，退B。

| 口径 | 人工复算 | 金额 |
| --- | --- | --- |
| 开发与测试共同采用的假设 | B分摊优惠：50×99÷357，四舍五入到分为13.87；99−13.87 | 85.13 |
| 独立财务规范 | 剩余A+C=258，小于300，剩余优惠重算为0；退款=307−(258−0)，等价于99−50 | **49.00** |
| 差额 | 85.13−49.00 | **36.13** |

同一订单依次退B、C、A分别退款49、59、199，累计307；重复SKU不产生新增退款。低价商品使优惠失效且公式为负时暂停支付、转人工确认，不产生负退款。金额使用Decimal，假设按“先舍入优惠份额，再计算退款”处理尾差。

V1.0未明确精确7日时间算法、审核超时、运费或渠道重试；这些保持待确认，AI假设不能成为事实。V1.1明确普通/银卡7×24小时、金卡15×24小时，截止时刻含端点，按下单时等级；以订单时区时间戳比较。极速资格由固定上游 `eligible` 标识输入，不建设风控系统；质检失败只演示测试影响、追偿/人工处理状态，不执行真实追偿或支付。

## V1.1增量统计

当前资产扫描结果：历史32条；27保留、4修改、1作废；15条新增候选中1条已由修改后的旧用例覆盖，真正新增14条；目标总数45条，实际回归25条全部通过。

31条历史用例的依赖链受影响，但只有5条发生行为处置（修改4、作废1）；21条已验证财务用例仅增加正式需求来源。页面对比“整套重生成45条”与“行为新增/修改18条”，并单列来源更新和作废，不把所有来源调整伪装成算法变化。所有数字由代码派生，修改资产后以实际输出为准。

## Reset与异常恢复

页面不使用localStorage，不修改稳定业务资产。阶段、预算和执行报告只存在浏览器内存；刷新始终回到课堂起点。全局重置与CLI复位更新共享本地序号，已打开页面约3秒自动恢复Demo2／阶段1、预算15、未补漏、无执行结果、财务隐藏；休眠或断开服务的页面请刷新。Reset不删除实践导出文件或修改源码。

1. 页面报错：点“重试”；仍失败就Reset并刷新。重试会重新请求本地服务。
2. 服务停止：回终端重新 `make dev`，再刷新；端口冲突改 `PORT`。
3. 材料损坏/缺失：`make validate`定位问题；恢复本项目对应稳定资产后重新验证。Reset只恢复演示状态，不声称修复被人为修改的PRD、代码或用例。
4. 投影或浏览器异常：使用下面真实命令行输出兜底，AI内容仍明确是预置结果。

```bash
.venv/bin/python scripts/run_demo.py --demo 3 --budget 15 --manual
.venv/bin/python scripts/run_demo.py --demo 4          # 先只展示20/20执行报告
.venv/bin/python scripts/run_demo.py --demo 4 --reveal # 再揭示财务依据和49.00
.venv/bin/python scripts/run_demo.py --demo 6          # 增量动作及实际回归
```

课前必须确认 `DEMO READY` 和投影可读性。课后及重新完整演示前Reset一次；冻结AI输出无需网络，也无需API密钥。实际投影设备、讲师讲述节奏、上游资格标识与所采用的构造业务规则仍需讲师人工确认。本项目是虚构课堂案例，不作为真实商城售后政策。
