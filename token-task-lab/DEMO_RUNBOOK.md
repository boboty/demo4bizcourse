# DEMO_RUNBOOK

> 课堂实际使用入口：启动 `uvicorn app.main:app --port 8014` 后打开 **http://127.0.0.1:8014/runbook**。
> `static/runbook.html` 将本页内容组织成单页讲师驾驶舱，并自动读取 Provider、Token 证据和最近实验状态；本 Markdown 保留为教学逻辑与台词的文字源。

## Provider 固定配置

本课程 Demo 固定使用 DeepSeek：

- Base URL：`https://api.deepseek.com`
- Model：`deepseek-flash`
- 课堂唯一必填：`LLM_API_KEY`

不在课堂临时切换 base URL 或模型，避免实验条件变化。

`.env` 会自动加载。首次准备只需要：

```bash
cp .env.example .env
# 编辑 .env，填入 LLM_API_KEY
```

以后直接启动即可，不需要再 `export`，也不需要 `uvicorn --env-file`。

## 课堂位置

### Demo 1｜第二讲“四问”之后

不要重新开场，直接接：

> 刚才说条件拿不到就应该停，我们直接看它会停在哪里。

1. 打开天津货代场景。
2. 输入客户原话，选 C 档，运行。
3. 逐条念「本次运行的实际业务结果」：AI 实际任务理解、AI 实际识别缺口、
   本次事实获取结果、业务判断、校验、最终停止点。**这些是这次真的跑出来的。**
4. 停在「本次事实获取结果」：船期=有结果但未核验，运价=无结果，舱位=无结果。
   带出「拿到了 ≠ 能用」。
5. 需要时展开底部「场景验收基准」：说明那是课前写定的对照答案，不是 AI 的输出。
6. 不打开 Token 面板。

目标：验证“四问”是任务设计条件，不是抽象框架。

注意：如果现场改过输入（例如换成青岛→仁川），基准区会自动提示“已不适用”，
此时只看上方实际结果，别念基准。

### Demo 2｜第三讲调用链之后

直接说：

> 刚才从正面看是一件事，现在把同一次运行翻过来看背面。

1. 使用 Demo 1 的同一 `run_id`。
2. 打开运行背面。
3. 先看调用步骤，再看 usage。
4. 强调：任务数 ≠ 调用次数 ≠ Token 数。C 档是 6 个步骤、5 次模型调用、3 次工具调用。
5. 步骤表最后一列是 provider 报的 `finish_reason`，也就是“这次调用为什么结束”。
   正常结束是 `stop`；如果某一步是红色的 `输出被截断`，说明它撞到了输出上限、
   只写了一半，那一步的文字与 Token 都不能当完整结果讲。课件的冻结实验里不应出现这一标记。
6. 运行/回放 A、B、C；时间允许再看 D。

#### 实验对照（第三讲主画面）

页面上的「实验对照」把一次 A/B/C/D 的四个档位放在同一张表里，共用同一个
`experiment_id`，点任意一行就地展开那次运行的调用链——同一件任务、同一批实验，
不用从 runs 目录里挑四条时间不同的记录拼。

表里有两列要分开念：

- 「Token 证据」：只有 `Token 已计量` 的行才能拿来对比 Token。真实调用但 provider
  没返回 usage 的记录会被标成 `不可用于 Token 实验`。
- 「输出完整性」：`输出完整` 才是完整交付。出现 `输出被截断 N 次` 说明那一档有步骤
  撞到了输出上限（`finish_reason=length`），写下来的只是模型当时想说的前半段——
  这时 Token 数字仍然真实，但**内容不完整**，这一档不能用来讲“完整结果”，
  页眉也会直接写明哪几档不可冻结。

#### A 档两种现场结果都成立

- 若模型编造船期/价格：只问来源、舱位、价格依据，不重新讲“验证为什么重要”。
- 若模型谨慎停下：指出它自己暴露了缺失条件，直接推进 B。

#### D 档

必须是真实执行出来的低效版本，不能改数字。

## 课前准备

课堂默认回放已验证记录。`.env` 已经填好 API Key 后，上课前直接跑：

```bash
python scripts/record_runs.py        # 真实执行 A/B/C/D，写入 runs/
```

四档共用同一个 `experiment_id`，页面「实验对照」区可以直接整组回放。
脚本打印的对比表就是讲 D 档时的底稿。

看最后两行：

```text
课堂可用于 Token 实验的记录：N/4 档
适合课堂冻结的档位：N/4 档（Token 已计量 且 无 finish_reason=length 截断）
```

**两行都必须是 4/4。** 第一行只说明 Token 计量完整；第二行才说明输出也完整。
只要有一档真实调了模型却没拿到 usage，或者有一步被长度上限截断（输出只有前半段），
脚本会逐档警告、把它排除在可冻结之外并以非零码退出。失败且未落盘的档同理。

各档对比表最后一列是「截断」次数，大于 0 的档位不要作为完整结果使用。

仓库内另存有一份 C 档结构示例记录（`evidence_level=structure_only`，Token 字段为 null），
用于确认回放链路本身可用；它不是「已验证记录」，别拿它当真实用量讲。

## 课堂故障策略

- 预先保存一份完整、已验证运行记录（见上）。
- 网络/provider 异常时直接回放，不现场排障。
- 真机和回放结果不完全一致是允许的；课堂讲的是结构，不是追求固定答案。
- 完全没有 provider 时页面仍可打开：回放记录照常，现场运行只会得到结构示例。
