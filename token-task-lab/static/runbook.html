1｜环境准备：课堂只填 API Key

代码固定使用 https://api.deepseek.com 和 deepseek-flash。本目录的 .env 会自动加载，不需要额外 export，也不需要 --env-file。

首次准备

git pull
cd token-task-lab
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# 编辑 .env，只填 LLM_API_KEY
pytest -q

每次上课前

cd token-task-lab
source .venv/bin/activate
python scripts/record_runs.py
uvicorn app.main:app --port 8014
录制脚本最后必须出现：课堂可用于 Token 实验的记录：4/4 档，并且适合课堂冻结的档位：4/4。前者只说明 Token 计量完整；只要有任何一档出现 finish_reason=length 截断，输出就不完整，不能拿这组数字做课件或课堂对比。

2｜课前验证

先自动看状态，再人工确认一次课堂关键点。勾选项保存在本机浏览器。

3｜Demo 1 · 第二讲：先看业务正面

刚才说条件拿不到就应该停，我们直接看它会停在哪里。
1
输入客户原话，选 C 档运行。
天津新港到釜山，下周三货好，两个20GP，帮我看看船期和价格。
2
逐条看：AI实际任务理解 → 实际识别缺口 → 本次事实获取 → 业务判断 → 校验 → 最终停止点。
3
停在事实获取：船期=有结果但未核验；运价=无结果；舱位=无结果。
拿到了 ≠ 能用。
4
需要时再展开“场景验收基准”。强调：那是课前写定的对照答案，不是 AI 本次输出。
这里不要打开 Token 背面。第二讲只证明任务边界、资料条件和人工确认点。

4｜Demo 2 · 第三讲：把同一次运行翻到背面

刚才从业务正面看是一件事，现在把同一次运行翻过来看背面。
1
保持 Demo 1 的同一 run_id，点击“查看运行背面”。
2
点击“重放 Token 生成过程”：大号数字从 0 开始，按记录里的步骤顺序一步步长大；每一步的起点和终点都是这条记录里的真实读数。
3
到“获取事实”这一步时停一下：动作在变，Token 不动——工具调用不产生模型 Token。
4
重放结束后，再点“查看这 N Token 从哪里来的”回到步骤表看机制：解析 → 判断缺口 → 获取事实 → 判断 → 校验 → 输出。
5
最后看系统侧：C 档是 6 个步骤、5 次模型调用、3 次工具调用。
一件业务任务，不等于一次模型调用。

最后才落到输入 Token / 输出 Token / 缓存 / 总量。任务数 ≠ 调用次数 ≠ Token 数。

步骤表最后一列是 provider 报的 finish_reason，也就是「这次调用为什么结束」。若出现红色的 输出被截断，说明那一步撞到了输出上限、只写了一半：它的文字和 Token 都不能当正常完整结果讲，课件的冻结实验必须整组没有这一标记。

5｜第三讲主画面：A / B / C / D 同屏实验

使用同一个 experiment_id 的四档记录。只有“Token 已计量”的行才参与对比。

A｜直接回答

只有客户原话。若编造，问来源；若谨慎停下，也成立。

B｜全量上下文

一次把可用资料全部塞进去。重点观察输入 Token 如何变化。

C｜任务链

合理版本：按步骤在需要的时候拿资料、判断、校验。

D｜低效版本

同一业务目标，但真实执行重复上下文、重复解析、重复判断、重复校验。不要手改数字。

该花的 Token 要花，白花的 Token 要省。

6｜课堂故障策略

Provider / 网络正常

可以现场跑一档作为彩蛋，但主讲仍优先回放课前验证过的完整实验。

Provider / 网络异常

立即回放已保存实验，不现场排障。课堂讲的是结构，不是现场运维。

真机和回放结果不完全一致是正常的。课件引用的是冻结实验记录，不是“行业固定 Token 值”。
