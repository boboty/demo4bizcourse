1｜环境准备

第一次准备或代码更新后走一遍。已经进入课堂现场时，这一段可以在“课堂模式”中隐藏。

A. 更新与安装

git pull
cd token-task-lab
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

B. 先验测试

pytest -q

当前基准：88 项测试。数量以后可能增加，关键是全部通过。

C. 配置真实 Provider

export LLM_BASE_URL="你的 OpenAI-compatible API 地址"
export LLM_API_KEY="你的 API Key"
export LLM_MODEL="课堂使用模型"

第一次正式实验先不配 LLM_STRONG_MODEL，先把“重复上下文 / 重复步骤”这个变量讲干净。

D. 启动

uvicorn app.main:app --port 8014

Demo：http://127.0.0.1:8014/　Runbook：/runbook

2｜录一组可进课件的真实 A/B/C/D

课件里的数字来自固定的一组真实实验。不要手填，不要从不同时间的散记录拼表。

python scripts/record_runs.py | tee experiment-01.txt
通过标准
脚本最后必须出现：课堂可用于 Token 实验的记录：4/4 档。
不要进课件
只要不是 4/4，就先修 Provider / usage。真实调用但没有 input/output Token，不算课堂 Token 证据。

冻结规则

  • 找到一组差异清楚、4/4 可用的实验后，记住它的 experiment_id，作为课程基准实验。
  • 课件注明：固定模型与固定任务条件下的一次真实运行记录；Token 数量用于观察调用结构，不代表行业固定消耗。
  • 后续现场真机跑出不同数字没问题，课件仍使用冻结的基准实验。

4｜Demo 1 · 第二讲“四问”之后

目标：证明“四问”是企业任务能够交出去的实际条件。此时不要让 Token 抢戏。

刚才说条件拿不到就应该停，我们直接看它会停在哪里。
1
选 C 档，使用天津货代原始询价，运行或回放基准 C 档。
不要先打开运行背面。
2
按顺序看“本次运行的实际业务结果”：
AI 实际任务理解 → AI 实际识别缺口 → 本次事实获取结果 → 业务判断 → 校验 → 最终停止点。
3
停在事实获取结果。
船期＝有结果但未核验；运价＝无结果；舱位＝无结果。
拿到了 ≠ 能用。
4
需要时才展开“场景验收基准”：说明它是课前写定的验收答案，不是本次 AI 输出。
5
如果现场换成青岛→仁川等新输入，看到“基准已不适用”后，只讲上方实际运行结果。
这里不要讲：Token 数、为什么要验证、Token 效率。验证归第二讲四问，Token 留给第三讲。

5｜Demo 2 · 第三讲调用链之后

目标：把 Demo 1 的同一件业务任务翻到系统背面，看到一件任务如何变成多次调用。

刚才从正面看是一件事，现在把同一次运行翻过来看背面。
1
沿用 Demo 1 的同一个 run_id，打开“运行背面”。
2
先看步骤，不先看总数：解析 → 判断缺口 → 获取事实 → 判断 → 校验 → 输出。
3
再看汇总：C 档是 6 个步骤、5 次模型调用、3 次工具调用；Token 使用本次真实记录的数值。
一件业务任务，不等于一次模型调用。
4
只用一句话正式命名：任务数 ≠ 调用次数 ≠ Token 数。不要在这里展开 tokenizer 科普。

6｜第三讲主画面 · A/B/C/D 实验对照

同一件任务、同一批实验、一个 experiment_id。先比较“怎么做”，再比较“花了多少”。

A｜直接回答

只给客户原话。

若编造：只验来源；若谨慎停下：它自己暴露了缺失条件。两种都成立。

B｜全量上下文

一次性把可用资料都塞进去。

观察输入 Token 上升，以及“上下文多”是否真的等于“任务做得好”。

C｜任务链

该查时查、该判断时判断、缺事实就停。

这是主版本。不能脱离任务完成质量谈 Token 效率。

D｜低效版本

重复装载、重复上下文、重复解析、重复判断、重复校验，全部真实执行。

该花的 Token 要花，白花的 Token 要省。

对照时按这个顺序讲

  1. 先确认四行的 Token 证据＝已计量，否则不要比较数字。
  2. 比较模型调用 / 工具调用：一件任务背后结构不同。
  3. 比较输入 Token：B 和 D 为什么增长，分别是“业务资料增加”还是“重复浪费”。
  4. 比较任务结果：Token 高不等于坏，必须同时看它增加的是有效工作量还是低效工作量。
  5. 最后只用 C vs D 收束，不需要给 A/B/C/D 排一个“绝对冠军”。

7｜课堂故障策略

Provider / 网络突然失败

立即切到已保存的基准实验回放，不现场排障。台词：“现场调用失败不影响我们看结构，我直接切到课前真实跑过的这一组。”

现场真机数字和课件不一样

正常。课件是冻结的一次基准实验；现场运行是另一轮随机生成。讲结构，不追求数字复现。

A 档没有编造，反而很谨慎

更好。直接指出：“它自己告诉我们条件不够。” 然后进入 B，不要为了预设剧情诱导模型胡编。

某一档真实调用但 Token 证据不可用

不要现场拿这一档做 Token 数值比较。切回 4/4 classroom-ready 的基准实验。

时间不够

优先保：C 的正面 → 同一 run 翻背面 → C vs D。A 只用保存输出验货，B 可以压缩讲。
