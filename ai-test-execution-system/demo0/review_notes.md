# AI 初稿约束审查

初稿没有明显违背业务语义，但还不能直接交给稳定的真机执行器：

- 没有说明执行目标必须是 USB 连接的 iPhone Safari，也没有说明设备标识只能从本机环境变量读取。
- 没有明确固定测试账号，或登录前怎样确认该用户存在。
- “有一笔待付款订单”没有指定由哪个 API 重建，也没有说明 `order_id` 必须从 API 响应取得。
- 没有固定 UI 版本；本轮必须使用 V1，支付定位器是 `#pay-now`。
- “支付成功”只描述了 UI 文案，未区分页面结果和订单、支付、库存等业务事实。
- 没有定义最终 API 断言：`PAID`、一条 `SUCCEEDED` Payment、库存为 9。
- 没有要求失败时保存截图、Appium/设备执行日志、当前步骤和可获得的 API facts。
- 没有 cleanup，下一次演示可能受到上一笔支付订单污染。

这些约束在 `cases/pay_order.yaml` 中补齐。该文件是 Round 1 runner 的唯一用例输入；runner 不在运行时引入 AI 或修改 locator。
