# Demo B 讲师操作剧本：提示词注入与智能体越权

对应课件第 30 页演示；前接第 28–29 页的间接注入与越权提案，后接第 31–34 页的后端拦截、审计和纵深防御。完整课堂环节建议 12–15 分钟，纯操作约 3–5 分钟，解释、提问和对照约 9–10 分钟；可选深入讨论另行调配，不计入此区间。

## 与课件备注的教学映射

备注原设想包含只读账号登录、四个工具和摘要。当前页面采用服务端固定身份 `buyer-017`，用正常查询展示只读动作、用越权提案展示审批动作；读取后的采购状态用于课堂对照。讲师应说明这是聚焦模型提案与后端授权的简化映射，不声称逐字实现完整登录、四工具清单或摘要生成。B 页面无真实模型，结果为离线确定性模拟；审批状态只存在本地隔离沙箱。

## 起点与课堂主线

由第 29 页“你认为提案会不会执行？”的举手问题转入 `/demo/b`。确认健康提示正常，点击“重置演示”，两侧状态均为“待审批”。

| 操作 / 停顿点 | 屏幕应看到什么 | 讲师说明 |
| --- | --- | --- |
| 1. 点击“运行正常查询” | 固定用户请求、正常检索结果及只读提案；安全模式完成读取，采购单仍待审批 | 先建立正常基线：只读身份完成授权范围内的查询。 |
| 2. 点击“检索污染文档” | 用户请求不变；检索文档出现伪造指令，模型提案变成审批写操作 | 数据中的指令不因此成为可信系统指令。请问学员：请求没变，变化来自哪里？ |
| 3. 停在“模型提出的动作”卡片 | 显示越权动作及目标对象；尚未执行 | 模型“想做什么”和系统“允许做什么”是两件事。先不急着点击，让学员预测结果。 |
| 4. 点击“故障模式：执行越权提案” | 故障侧实际变为“已批准”，安全侧仍待审批 | 这是特意构造的本地故障模式，跳过授权后状态确实改变；只影响隔离虚构采购单。 |
| 5. 点击“安全模式：执行同一提案” | 同一运行、对象和动作被后端拒绝；安全侧仍待审批 | 后端按身份、对象和动作独立授权；模型输出和提示词不是权限边界。 |

**可选技术深入：**展开“技术详情：运行标识、请求标识与审计记录”，查看授权结果及前后状态。仅在有时间时重放安全模式一次，观察状态不变、审计追加；技术详情和完整响应不属于手卡主操作。第 31–34 页再讲失败链路、拦截点及纵深防御。

## 收口与复位

总结：检索文档是数据，模型输出是提案，后端授权决定动作是否执行，审计记录支持追溯。使用顶部“重置演示”恢复两套待审批状态并清空本次运行和审计；重启服务也会清空内存状态。按动态主操作顺序推进即可。

## 技术备用

浏览器失效而服务正常时，可运行 `uv run --offline python scripts/http_smoke.py` 作为真实 HTTP 备用路径，并明确它不是页面操作。请求失败查看页面错误与请求标识、服务终端，修复后刷新并重置。8016 处理见环境清单；可用临时 8017 服务供讲师手动打开页面，但固定端口的 smoke 脚本不能据此作为 8017 验证。
