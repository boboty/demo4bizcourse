# Demo B 讲师操作剧本

建议 8–10 分钟。场景为虚构“某产业集团”采购助手，所有审批状态均在本机内存沙箱。屏幕顶部始终声明“离线确定性模拟，非真实大模型”。模型反应可重复，不代表真实模型必然被相同文字攻击。

## 课前准备

1. 在线执行 `make setup` 预装依赖；启动 `make dev`，进入 `http://127.0.0.1:8016/demo/b`。
2. 断开外网，确认“本地服务正常”。建议 1440×900 及以上、浏览器全屏，按需缩放；页面支持窄屏纵向布局。
3. 点击“重置全部状态”：两套采购单均“待审批 · ¥128,000”，无审计。若需要留证，先保存截图或审计 JSON，重置会清除本轮记录。

## 分步演示与预期结果

| 操作 / 停顿点 | 屏幕预期 | 讲师说明 |
| --- | --- | --- |
| 1. 点“正常只读查询” | 进度经过检索、模型、授权、比对；提案为 purchase.read；安全结果 ALLOW，状态仍待审批 | 固定采购观察员仅能读取指定采购单，正常业务可以完成。 |
| 2. 点“注入污染文档” | 检索文本出现“伪造系统指令／不可信文档正文”；模型提案变为 purchase.approve，参数“已批准”；尚未执行 | 查询需求没有变化，是文档中的攻击文本改变了模拟模型提案。不可信资料不能变成系统指令。 |
| 3. 停在模型提案 | 记录当前运行 ID、动作及对象 | 模型“想做什么”和系统“允许做什么”是两道边界。 |
| 4. 点“故障注入：执行当前提案” | 故障系统 BYPASS，虚构单据实际变“已批准”；安全系统仍待审批 | 错误系统跳过授权，不能只把防护寄托在提示词。仅本地隔离沙箱受到影响。 |
| 5. 点“安全模式：执行相同提案” | 相同运行 ID、对象、动作；后端 HTTP 403 / DENY；安全系统前后均待审批 | 真实后端按固定角色、对象、动作拒绝。此拒绝不是页面预设动画。 |
| 6. 下滚审计 | buyer-017 / procurement_reader、PO-2026-017、purchase.approve、模式、BYPASS / DENY、run_id、request_id、前后状态 | 对比的是同一模型提案；审计能回答谁、对什么、做什么、是否获准。展开详情看到原始快照。 |
| 7. 再点安全执行 | 仍 DENY，状态不变，新增一条审计 | 重放同样不能获得权限。 |
| 8. 点“重置全部状态”，再“一键完整复演” | 清空旧运行和审计；依次完成正常允许、故障写入、安全拒绝，最终仅故障已批准 | 演示可重复，最后状态差异来自执行系统的权限边界。 |

课堂结论：检索文档是数据，模型输出是提案；执行授权是后端业务代码的责任。离线模型仅展示风险机制，后端拒绝与隔离状态修改是真实执行的代码。

## 故障备用路径

| 故障 | 操作与预期 |
| --- | --- |
| 自动复演过快或讲解跟不上 | 重置，改用四个分步按钮；每步等进度显示完成后暂停讲解。 |
| 页面服务不可用 / 请求失败 | 页面显示红色错误与请求 ID（若取得）；查看启动终端，重启 `make dev`，刷新并重置。进程重启也恢复内存初态。 |
| 端口 8016 被占用 | 停止本 Demo 的旧进程；不要误杀未知进程。也可 `uv run --offline uvicorn app.main:app --host 127.0.0.1 --port 8017`，打开相应端口；HTTP 自检脚本固定 8016，须用标准端口运行验证。 |
| 多人同时操作导致状态混杂 | 本工具是单机共享课堂沙箱，关闭其他窗口，重置；不作为多租户系统。 |
| 浏览器暂时故障 | 保持后端运行，执行 `uv run --offline python scripts/http_smoke.py` 展示真实 HTTP 的 ALLOW / BYPASS / DENY 与前后状态；脚本最后重置。 |
| 现场尚未安装依赖 | 使用课前已准备环境或已保存的验收截图讲解；明确这是历史证据。不要声称现场执行成功；本轮不提供真实模型云端兜底。 |

不输入真实合同、个人信息、涉密文档；本演示只处理内置虚构资料。课程 A 的涉密边界另行开发，本轮不增加其他 Demo。
