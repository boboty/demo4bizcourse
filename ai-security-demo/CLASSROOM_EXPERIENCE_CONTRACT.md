# 四 Demo 课堂体验验收契约

本契约用于 A、B、C、D 体验重构及独立验收。工程行为与本契约冲突时，保留后端授权、拒绝、安全隔离、审计和重置语义；前端调整必须继续通过现有安全验收。

## 共用课堂工作区

- 验收视口固定为浏览器内容区 `1440×900`；初始页和每个主要步骤的主要操作、核心业务资料/状态、该步反馈同屏出现，课堂主流程不要求上下滚动或跨页寻找结果。
- 页面固定呈现“当前步骤、已完成步骤、下一步”；当前步骤有醒目的文字和视觉状态，已完成步骤与未开始步骤可区分，不能只依赖颜色。
- 每一步最多一个视觉主操作。其它操作（重置、完整复演、边界分支、导出和技术入口）需明确弱化；当前不适用的操作保持禁用。
- 操作与反馈相邻：课堂结论/执行反馈在操作区域或对应业务状态旁即时更新，提供可读的成功、拒绝或待核查信息。
- 用业务字段前后变化、证据高亮和安全/故障对照讲清机制；用短句提示边界，不让长技术说明成为主叙事。
- 投影检查：常规正文不小于 18px 左右，关键结论和业务状态明显更大；对比度充分；不以红绿颜色单独传达状态；中文标签优先。
- 请求标识、审计 JSON、规则细节、原始长日志及调试信息放入可选折叠区，默认不争夺主视觉焦点。
- 随时可一键重置到可复演初始状态；重置后关键业务状态、运行和审计符合原有独立 Demo 语义。
- 四页使用同一 BenYan Design System tokens、页面导航、步骤组件、反馈区、主次按钮和工作区间距。A/C/D可按内容选择记录、证据或表单布局；B必须把同一提案与安全/故障业务状态对照放在焦点区。
- 不加载在线字体、CDN、外部脚本、网络模型或真实企业数据，断网可完整运行。

## 各页可观察结果

| 页面 | 课堂故事 | 主要可观察结果 | 安全边界 |
|---|---|---|---|
| A 文档处理 | 合同原文 → 辅助识别 → 人工核查 → 授权与脱敏 | 原文命中高亮、规则/辅助分类对照、人工误报修正、脱敏前后字段对照；未授权和涉密作为快速分支 | 虚构身份证号和手机号不对应真实个人；识别不授予权限；涉密入口前阻断 |
| B 提示注入 | 正常查询 → 污染文档 → 越权提案 → 故障/安全执行对照 | 原始请求保持不变；恶意文档、模型提案和执行结果并列；故障沙箱状态改变，安全沙箱由真实后端拒绝且状态不变 | 隔离故障状态、后端授权、审计和重置保持原样；不可用预设动画替代后端执行 |
| C 合规审计 | 异常记录 → 规则命中 → 辅助解释 → 人工核查与认定 | 一条聚焦案例随步骤揭示原始证据、规则依据、AI解释、人工结论 | AI解释不是违规认定；人工证据引用和理由仍由后端校验 |
| D 事件研判 | 日志线索 → 聚合 → 辅助研判 → 四栏简报 | 可观察线索收敛为事实、推测、待核查、建议四栏 | 推测不得成为事实；不自动封禁、隔离或执行建议 |

## 独立真实浏览器验收

1. 真实浏览器在 `1440×900` 打开 A/B/C/D 四路由，确认没有页面错误，所有资源和操作不发起外网请求。
2. 对每页从初态开始，记录每一步的操作路径；完成一个可重复的课堂主流程，并逐步检查操作与结果同屏、当前/完成/下一步状态、可读性及安全/拒绝分支。
3. 对重置进行一次检查，并重复主要流程，确认状态可恢复。
4. 每页保存初始和关键结果视口截图；证据说明必须标注路由、视口尺寸、截图时的流程步骤、操作路径，以及任何录屏/交互覆盖限制。
5. 截图、录屏和本地运行输出存于 Git 忽略的 `evidence/` 目录。自动测试结果不能取代人工视觉和交互判断；必须逐项报告检查证据与未覆盖项。

## 后续独立验收分工

- A 实现任务：合同原文、高亮、人工误报修正、已授权/未授权/涉密分支与脱敏对照；同时复核既有授权、隔离、审计和虚构个人信息约束。
- B 实现任务：不改既有 Human 接受历史；验证真实检索、污染驱动提案、同一原始请求和提案、安全/故障后端执行、隔离状态变化与审计/重置。
- C 实现任务：单案例叙事、证据和规则可追溯、AI解释与人工认定区分、前后端人工核查保持。
- D 实现任务：合成日志到聚合线索、推测与事实分栏、可核查四栏简报，以及不自动执行处置。
- 集成体验验收：四路由共用视觉与交互框架，执行本契约“独立真实浏览器验收”全量检查，并逐页提供路径和关键截图。A/B/C/D 各自的任务级 verifier 结论不能代替此集成验收或 Human 接受。
