# Demo C 讲师操作剧本：AI 使用合规审计与人工认定

对应第 45 页演示，前接第 43–44 页治理机制与角色分工，后接第 46 页证据阶梯回顾。完整课堂环节建议 15–18 分钟，纯操作约 5–7 分钟，解释、核查和互动约 10–11 分钟；可选深入讨论另行调配，不计入此区间。案例、平台日志、制度、身份均为虚构；页面只运行离线确定性规则和模拟解释。

## 起点

由“治理机制如何落地、谁负责认定”转入 `/demo/c`。确认本地服务正常，默认案例标题为“采购纪要 · 违规线索”。默认选例适合展示未准入工具线索；可通过案例卡内“查看完整原始日志、制度条文与案例列表”切换到证据不足或常规案例，但主线不需要切换。

## 课堂主线

| 操作 / 停顿点 | 屏幕应看到什么 | 讲师说明 |
| --- | --- | --- |
| 1. 点击“建立审计案例” | 本次审计对象及其业务背景出现，后续步骤关联同一案例 | 先看业务记录是什么，不急着下违规结论。 |
| 2. 点击“查看规则线索” | 确定性规则命中及相关制度/字段线索 | 命中说明值得核查，不等于违规成立。请学员说出还缺哪类证据。 |
| 3. 点击“生成辅助解释” | 离线辅助解释、待核实项和原始证据卡出现；最终结论仍为空 | AI 卡片把线索整理成解释，但推测必须回到原文核对。 |
| 4. 阅读每张相关证据的“阅读完整证据原文”，勾选需核对项，再点击“记录证据核对” | 证据阅读/核对状态更新；材料不完整时页面仍标明不足 | 请停顿让学员比较日志、审批与制度。不能只看摘要；若有关键字段缺失，选择“证据不足”是合理结果。 |
| 5. 在人工认定区选择结论、填写理由，点击“提交人工认定” | 页面显示人工结论与关联证据；固定身份为合规审计员 | 只有人工核对证据、填写理由并提交后才形成认定。避免把离线解释说成结论。 |

候选问题 JSON 是交付给后续核查的清单，不是定性报告；如需展示，在主线完成后点击“导出候选问题清单 JSON”。无需展示原始 JSON 内容。回顾第 46 页时不重复操作 Demo。

## 收口与复位

结论：规则负责筛查，辅助解释帮助定位，原文证据支撑人工认定；缺证时保留待核实。点击“重置 C”清除 C 本轮运行和审计；不会影响 A/B/D。重启服务同样恢复内存初态。

## 技术备用

浏览器故障但服务正常，可用 `uv run --offline python scripts/http_smoke_c.py` 展示 HTTP 链并说明这是接口备用。页面失败先看错误提示和请求标识、服务终端；服务恢复后刷新并重置 C。端口处理见 `CLASSROOM_ENV_CHECKLIST.md`。
