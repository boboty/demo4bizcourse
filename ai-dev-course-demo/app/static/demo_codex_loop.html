Demo 2 · 完整任务包驱动研发闭环

同一份完整任务包，这次由主代理统筹计划与门禁、代码子代理负责执行，独立验收代理最终对照目标给出 PASS。

课堂演示说明（讲师用，点击展开 / 收起）

本轮给AI的命令

不是一句命令，而是左侧完整任务包原文——由主代理读取后拆解、派发给代码子代理执行。

当前演示什么

模拟主代理读取任务包并制定计划，派发代码子代理执行；子代理提交实现与验证证据后，主代理执行阶段门禁，因全量验证证据不足驳回一次；子代理补充全量验证后，主代理放行；最终由独立验收代理重新对照任务包给出 PASS。

固定演示步骤

  1. 先展示左侧完整任务包，强调目标、边界和验收标准。
  2. 点击“提交任务包并开始执行”。
  3. 在“02·主代理制定执行计划”阶段停顿，指出主代理拥有计划权和调度权。
  4. 在“03·主代理拉起代码子代理”阶段强调：完整任务包被拆解为边界清楚的子任务。
  5. 在“05·主代理执行阶段门禁并驳回”重点停顿，强调驳回的是证据、不是代码错误。
  6. 在“06·代码子代理补充验证”展示全量测试 25 passed 的结果。
  7. 在“07·主代理门禁放行”强调门禁通过所依据的判断项。
  8. 在“08·独立验收代理最终验收”展示 PASS 结论与验收项证据。
  9. 收尾时展示四条观点钉子与主结论，并切换到 Demo 1 与 Demo 2 对照。

本轮结论

丝滑不是一路不停，而是任务定义清楚、分工明确、门禁有效，只在必要位置做一次低成本驳回。

提交给主代理的完整任务包

任务：为用户列表增加 Excel 导出功能

【任务目标】

为现有用户列表增加 Excel 导出能力，导出当前筛选条件下的全部结果，而不是当前分页数据。

【功能要求】

1. 用户列表页面增加“导出 Excel”按钮。
2. 导出复用当前 username 和 status 筛选条件。
3. 导出请求不得携带 page 和 page_size。
4. 未设置筛选条件时，应导出全部23条用户数据。
5. 空姓名、空字符串及空结果必须正常处理，不得导致接口异常。
6. 生成的文件必须是真实有效、可以正常打开和读取的 xlsx 文件。
7. 不得破坏现有用户列表、筛选和分页功能。

【技术约束】

1. 保持现有 FastAPI 后端结构。
2. 前端继续使用静态 HTML、CSS 和原生 JavaScript。
3. 不引入 React、Vue、Vite、npm 或外部 CDN。
4. 正式接口使用 /api/users/export。
5. 实现应尽量复用现有用户查询与筛选逻辑。
6. 不创建新的服务、端口、分支或 worktree。

【验收标准】

1. 默认状态导出23条数据。
2. username 筛选后，只导出匹配结果。
3. status 筛选后，只导出匹配结果。
4. username 与 status 组合筛选正确。
5. 导出请求包含筛选参数，但不包含 page 和 page_size。
6. 姓名为空的 bob 可以正常导出。
7. 无匹配数据时，仍生成合法 xlsx，表头正确且无数据行。
8. 文件扩展名、Content-Type 和 Content-Disposition 正确。
9. xlsx 文件可以被程序真实读取，记录数量与筛选结果一致。
10. 现有列表、筛选和分页功能无回归。

【验证要求】

1. 增加或更新自动化测试。
2. 运行完整测试集。
3. 使用真实浏览器执行默认导出、筛选导出和空结果导出。
4. 检查浏览器实际发出的请求参数。
5. 使用 xlsx 读取工具检查导出文件内容和行数。
6. 最终输出变更文件、验证结果、验收标准映射和残余风险。

这次交给AI的，不再只是一句话，而是一份包含目标、边界、约束和验收标准的工作定义。

08 · 独立验收代理最终验收

任务状态：PASS

主代理：完成读取、计划、派发与门禁判断（1 次驳回 + 1 次放行）
代码子代理：完成实现，提交两次验证（首次仅新增测试，二次全量测试 25 passed）
独立验收代理：重新对照任务包，最终 PASS

门禁历史：GATE REJECTED（验证证据不足）→ GATE PASSED
验收项：9/9 已覆盖
  • ✓ 导出全部筛选结果
  • ✓ 中文列名正确
  • ✓ 空列表正常
  • ✓ display_name 为空正常
  • ✓ 超过 10000 行返回 422
  • ✓ 复用已有筛选逻辑
  • ✓ 未改变原接口语义
  • ✓ 全量测试通过
  • ✓ 无越界修改

1. 主代理不必亲自执行每一步，但必须掌握计划、门禁和推进权。

2. 门禁不是让 AI 变慢，而是用低成本检查阻止高成本返工。

3. 执行完成不等于阶段通过；证据满足门禁，流程才能继续。

4. 最终验收仍然要回到原始目标，不能只接受执行者的完成声明。

丝滑不是一路不停，

而是任务定义清楚、分工明确、门禁有效，只在必要位置做一次低成本驳回。

模糊需求驱动

  1. 一句话开始
  2. 默认理解
  3. 功能出现
  4. 空值失败
  5. 补测试
  6. 测试通过
  7. 目标仍遗漏
  8. 再次修正
  9. 最终通过

问题不是AI不会写，而是工作没有被完整定义。

完整任务包驱动（多智能体协作）

  1. 目标与边界明确
  2. 主代理读取工程
  3. 主代理制定计划
  4. 派发代码子代理
  5. 子代理提交实现与证据
  6. 门禁驳回（证据不足）
  7. 子代理补充验证
  8. 门禁放行
  9. 独立验收 PASS

丝滑不是一路不停，而是任务定义清楚、分工明确、门禁有效。
