# 模糊提示与完整任务包对比

| 判断维度 | 模糊提示 | 完整任务包 |
| --- | --- | --- |
| 是否圈定代码上下文 | 未说明应读取哪些分层和既有工具 | 给出真实路径、关键函数和规则文件 |
| 是否明确工程约束 | 无法判断能否加依赖、改变接口或另写查询 | 明确不加依赖、不改无关模块、保持兼容 |
| 是否能逐条验收 | “有导出”只能检查入口是否存在 | 每项输出和边界都能通过接口或测试检查 |
| 是否处理空值、空列表和数量上限 | 没有行为约定，容易由实现者自行猜测 | 约定空列表、空显示名称和10000行拒绝行为 |
| 是否复用现有逻辑 | 可能复制筛选逻辑，形成两套口径 | 指定复用 `UserService.search_users` |
| 是否减少后续追问和返工 | 关键选择会在编码中或评审后暴露 | 在动手前就提供实现边界与完成定义 |

模糊需求的问题不是信息少，而是无法判断AI是否真正完成了任务。
