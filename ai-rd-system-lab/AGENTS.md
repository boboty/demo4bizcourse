# AGENTS.md

本目录用于长期维护 AI 研发体系建设 Demo。修改本目录时，优先保证课堂可复现性，而不是追求工程复杂度。

## 通用规则

1. 每个 Demo 只证明一个核心工程判断，避免把多个课程主题揉进同一个任务。
2. 所有课堂工程必须支持一键或单命令重置；reset 不应依赖网络。
3. 讲师侧 Golden Case、独立验收器、参考实现不得泄漏到开发 Agent 的工作目录或上下文。
4. 真实执行优先。静态模拟只允许作为故障回放、解释材料或现场兜底。
5. 故障可以通过固定 checkpoint 预制；修复链必须能够真实执行并留下测试/运行证据。
6. 课堂依赖应尽量少、固定、可离线准备；不要在现场临时下载依赖。
7. 每个 Demo 至少提供：reset、最小验证、完整验收、失败兜底四条路径中的适用项。
8. 新增规则、Skill、检查器前，先说明它解决的真实失败；避免为了完整感堆资产。
9. 与其他课程 Demo 不建立运行时依赖。若复用旧项目，复制稳定 baseline 后在本目录独立维护。
10. 不把模型、provider、思考等级写死为课程结论；这些属于运行环境和课前配置，除非 Demo 本身就在比较它们。

## 教学边界

- D0 只证明连续执行：环境反馈可以驱动 Agent 下一步动作。
- D1 证明工程现场与跨 Session 连续性。
- D2 证明证据来源与独立验证。
- D3 证明失败可以转成系统防复发能力。
- LAB 负责综合实战，不额外引入第五套理论。

如果一个修改会提前泄露后续 Demo 的答案，应优先隔离而不是复用。
