# AI 研发体系建设实验场

`ai-rd-system-lab/` 是 `demo4bizcourse` 中用于长期建设 **AI 研发体系** 课程资产的通用实验项目。

它不绑定某个行业、某次课或固定时长。后续研发课程中的连续执行、工程环境、长任务上下文、独立验证、能力沉淀、治理与综合实战，优先在这里演进。

## 目标

本项目不是模型能力展示仓库，也不是工具功能合集。

所有 Demo 都必须回答一个明确的工程问题，并能够稳定复现：

1. AI 能否连续执行真实研发动作；
2. 工程环境如何影响 Agent 的稳定性；
3. 执行结果如何获得独立、可验证的证据；
4. 一次成功或失败如何改变下一次研发的默认能力；
5. 自治扩大后如何保留边界、追溯与成本控制。

## 课程主线

当前研发体系建设主线：

```text
控制权迁移
  ↓
工程环境
  ↓
执行 ⇄ 证据
  ↓
自治边界
  ↓
能力沉淀与治理
```

项目可以服务不同课程，但 Demo 的工程语义保持稳定。

## 目录约定

```text
ai-rd-system-lab/
├── README.md
├── AGENTS.md
├── workspaces/          # 可独立运行、重置的课堂工程现场
├── instructor/
│   ├── tasks/           # 给执行模型/开发 Agent 的任务说明
│   ├── runbooks/        # 讲师现场操作手册
│   ├── checkpoints/     # 固定课堂起点/失败点/完成点说明
│   └── traces/          # 预跑轨迹与兜底证据
└── scripts/             # reset / verify / acceptance 等课堂脚本
```

目录会随 Demo 实现逐步补齐，不为“看起来完整”提前创建无意义资产。

## Demo 编号

Demo 编号描述能力，不绑定课程讲次：

- `D0`：连续执行 —— Agent 从环境反馈中自主决定下一步；
- `D1`：工程现场 —— Agent 能重新找到项目真实状态并持续工作；
- `D2`：独立验证 —— 执行侧全绿，但外部正确事实能够发现偏差；
- `D3`：能力沉淀 —— 旧错误再次出现时，系统能够自动阻止；
- `LAB`：综合实战 —— 任务基线、独立验证、修复与沉淀完整闭环。

编号只表达当前资产分组；后续可增加新 Demo，不强制所有课程完整使用全部资产。

## 基本原则

- **Demo 必须真跑。** 静态页面只能做解释或兜底，不能冒充真实 Agent 执行。
- **故障可预制，修复要可复现。** 不把课堂成功建立在“模型这次正好犯错”上。
- **每个 Demo 只证明一件事。** 不在一个 Demo 里同时塞 Spec、Golden Case、Skill、多 Agent 等多个主题。
- **独立验收不泄漏给执行侧。** Golden Case、教师验收器等必须与开发 Agent 的上下文隔离。
- **Checkpoint 优先于现场等待。** 掉队小组可以跳到固定状态，不让一个步骤拖垮后续教学。
- **资产必须可重置。** 每个课堂 Demo 都要有明确 reset / verify / fallback 路径。
- **不跨课程目录建立运行时依赖。** 可以从已有 Demo 复制稳定 baseline，但复制后在本目录独立演进。
