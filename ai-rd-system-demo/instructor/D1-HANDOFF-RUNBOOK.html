D1 · 工程现场接力

一个没有聊天记录的新 Session，还能找到自己站在哪里吗？

读工程现场 → 判断健康度 → 判断下一步 → 完成 → 写回状态

D1 的主 demo：全新 Codex session（--ephemeral，零历史记录）从同一个融资申请工程的"中途接手点"出发，只凭工程现场资产重新建立坐标。

工程现场设计

固定的"中途接手"起点

workspaces/d1-handoff/ 每次 reset 都重放同样的 3 次提交：

提交含义
chore: start financing filter+export task…任务刚开始，脚手架文件都在，功能还没做
feat(financing): add customer_name filter…客户名称筛选已完成并有测试，DECISIONS.md 记了 3 条决策
chore: session ended — see PROGRESS.md…空提交，显式标记"上一个 session 到这里结束"
文件作用
TASK.md原始任务 + 开发侧验收方向
PROGRESS.md当前做到哪里：已完成客户名称筛选，未完成状态筛选和导出
DECISIONS.md为什么这么做：筛选顺序、模糊匹配语义、类型注解写法
feature-list.json机器可读的功能级完成情况
verify.sh健康检查：跑现有 pytest
PROJECT-MEMORY.md / CODING-STANDARDS.md长期项目事实与规范，不随任务进度变化
Git History3 次提交，最后一条显式标记 session 已结束
D1 只用开发侧 verify.sh（本质是 pytest），不使用 Golden Case / 独立 Validator / 外部 Source of Truth（第三讲）；不引入 Skill / 规则生命周期 / 防复发资产（第四讲）。
现场先做预测

启动新 Session 之前，先预测五项

看一眼工程现场（不启动 Agent），预测新 session 会不会命中：

  1. 识别当前任务（客户名称 + 状态筛选 + 导出）
  2. 识别已完成项（客户名称筛选已做完）
  3. 识别下一步（状态筛选 + 导出）
  4. 识别一个关键决策（D-001 / D-002 / D-003 任一条）
  5. 使用正确的验证命令（./verify.sh）
即使某一项没命中，demo 也不算失败——没命中的项恰好用来讨论"工程现场还缺什么"。
接手运行

Reset，再新开一个 Session

cd ai-rd-system-demo ./scripts/reset_d1_handoff.sh cd workspaces/d1-handoff cat PROGRESS.md git log --oneline cd ../..

2 · 一条命令跑完整链路

./scripts/d1_handoff_run.sh --no-reset

或用交互式会话：从 workspaces/d1-handoff/ 目录新开 Codex（不要带着之前的会话），只粘贴下面这一句话：

接手当前任务。先判断项目现在做到哪里、当前是否健康、下一步应该做什么；确认后继续完成下一步，并把最新状态写回项目。

课堂观察点

屏幕上应该出现什么

节点屏幕上应该出现讲师要讲的一句话
读取工程状态命令引用 TASK.md / PROGRESS.md / DECISIONS.md / feature-list.json / git log它没有问我们上次做到哪了，而是自己去项目里找
识别当前任务消息同时出现客户名称、状态、导出三个范围任务边界不是刚才告诉它的
识别已完成项消息说"客户名称筛选已完成"它知道哪些不用重做
识别一个决策引用 D-001/D-002/D-003 或复述"权限→筛选→分页"它不只读了结论，也读了原因
判断下一步消息点名"状态筛选"和"导出"下一步来自 PROGRESS.md，不是猜的
先做健康检查执行 ./verify.sh，发生在第一次改代码之前先确认现状，再动手
完成真实小步骤app/financing/service.py、app/main.py 有新增代码不是只写文档，真的实现了
读取机器反馈改完后再次运行 verify.sh反馈进入了它的收尾判断
写回工程状态PROGRESS.md / DECISIONS.md / feature-list.json 内容变化下一个 session 能接着用
没有越界trace 里没有出现其他 workspace 或 instructor/reference 路径它老老实实待在自己的项目里

兜底

Session 超时或跑偏

cat instructor/d1/handoff/fallback/final.md cat instructor/d1/handoff/fallback/workspace.diff cat instructor/d1/handoff/fallback/result.json ./scripts/d1_handoff_restore_fixed.sh # 直接切到"下一步已完成"目标状态 ./scripts/reset_d1_handoff.sh # 回到接手起点再演一次
fallback 保存的是同一个 handoff checkpoint、同一句接手指令下真实跑通的一次完整运行，不是另一个项目的录像。
Checkpoint命令状态
handoff（起点）./scripts/reset_d1_handoff.sh3 个提交，客户名称筛选已完成，状态筛选/导出待做
fixed./scripts/d1_handoff_restore_fixed.sh状态筛选 + 导出均已完成，仅用于兜底
