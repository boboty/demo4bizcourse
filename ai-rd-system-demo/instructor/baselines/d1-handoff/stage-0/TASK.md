# TASK

> 给融资申请列表增加客户名称和融资状态筛选，并支持导出。

## 开发侧验收方向（不是独立验收标准，不含 Golden Case）

- 客户名称按模糊（子串）匹配；融资状态按精确匹配。
- 支持单条件、多条件组合筛选，以及空结果的处理。
- 筛选不能扩大 `PROJECT-MEMORY.md` 里已经建立的 tenant 数据权限范围。
- 导出复用既有的异步 `ExportQueue`（`app/common/export_jobs.py`），导出的必须是"当前筛选条件下的结果"，并携带发起用户的权限范围。
- 每个 feature 的"完成" = 后端行为（service 参数 + API query 参数）**加上**页面入口（用户能在 `static/index.html` 里实际点到、用起来，不是只有接口），再加上对应的开发侧测试；三者缺一都不算完成，见下面《功能完成定义》。

## 功能完成定义

`static/index.html` 是这几个功能目前唯一的用户入口（没有其它前端）。`feature-list.json` 里任何一个 feature 标记为 `done` 之前，必须同时满足：

1. **后端行为**：对应的 `service` 函数参数和 `app/main.py` 的 API query 参数都已实现，行为符合上面"开发侧验收方向"。
2. **页面入口**：`static/index.html` 里有用户能实际操作的入口（输入框/下拉框/按钮等），点击或输入后会真的把参数传给后端 API，不是装饰性的假控件；导出类操作要在页面上展示真实的后端返回结果（例如任务 id、状态），不能只展示一句前端写死的提示文字。
3. **对应测试**：有开发侧测试覆盖（后端行为测试 + 页面结构/连线测试），测试通过且被 `./verify.sh` 收录。

页面具体怎么实现（用输入框还是下拉框、按钮文案、DOM 结构、id 命名）不做规定，由实现者自行决定；只要求"用户真的能在浏览器里用"。
