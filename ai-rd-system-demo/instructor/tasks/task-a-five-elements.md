# 任务 A｜五要素可交办任务

## 一句话需求

融资申请列表增加客户名称、融资状态筛选，并支持导出。

## 01 背景｜为什么做

- 业务方每天手工导出、肉眼筛选，对账耗时且容易出错。
- 本期目标是把这段人工去掉，不改现有业务流程。
- 已定：不新增页面，在现有列表上扩展。

## 02 边界｜哪些能改，哪些绝对不能碰

- 可改：融资申请列表的查询、筛选与导出。
- 不可改：申请创建、审批流转、状态机逻辑。
- 模块隔离：不修改公共查询组件的默认行为。

## 03 约束｜有哪些必须遵守的既有规则

- 沿用现有分页规则与数据权限规则，不新开口子。
- 导出走已有的异步任务通道，不新增同步大查询。
- 不引入新的第三方依赖。

## 04 交付物｜最终交什么

- 后端查询接口 + 前端筛选组件 + 导出任务。
- 接口文档同步更新。
- 一次结构清晰、可回滚的 PR。

## 05 验收标准｜怎样证明对

- 运行：`pytest -q`。
- 独立验收由讲师在 workspace 外执行；开发 Agent 只运行开发侧测试，不读取独立验收脚本实现。
- 筛选组合必须覆盖：单条件、多条件、空结果。
- 导出的是当前筛选结果；导出任务必须保留 `customer_name`、`status` 和当前用户的数据权限范围。
- 导出字段必须严格与列表字段一致：`id`、`customer_name`、`status`、`amount`。
- 前端必须提供客户名称筛选、融资状态筛选和导出操作；只验收功能和行为，不约束 HTML `id`、`class` 或变量名。
- 越权访问用例必须失败；筛选不得绕过现有数据权限。

## 执行要求

1. 先读仓库结构和 `AGENTS.md`，先给 5 行以内执行计划。
2. 只在允许边界内改动。
3. 完成后只运行开发侧测试 `pytest -q`，独立验收由讲师在 workspace 外执行。
4. 最后列出：修改文件、验证证据、仍需人工确认的事项。
