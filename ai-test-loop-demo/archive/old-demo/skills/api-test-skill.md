# API 测试能力模板：业务规则闭环

## 输入要求

- OpenAPI 定义；
- 原始业务需求；
- 带 ID 的验收标准；
- 可重复的测试环境。

## 标准执行步骤

1. 解析接口、请求约束和响应字段；
2. 建立 requirement → acceptance → test 的映射；
3. 生成正常、异常、边界测试；
4. 为每条关键业务规则设计字段与决策过程断言；
5. 执行测试；
6. 保存统一格式的执行与覆盖证据；
7. 使用独立程序/角色重新对照验收标准验收。

## 强制规则

- HTTP 200 不等于业务成功；
- 必须验证业务状态和关键计算字段；
- 关键规则必须有独立证据，不能只以最终金额代替；
- 生成者不能只用自己生成的测试结果证明自己正确；
- 未通过独立验收的测试资产不得进入正式回归套件。

## 输出要求

每次输出都应包含：测试范围、AC 覆盖声明、执行结果、关键业务断言、未覆盖项、独立验收结论。报告中的结论应区分“pytest 通过”和“业务验收通过”。
